# expected 모델 목적함수 축 (L1 vs L2) — 실측 결과 (2026-07-29)

요일별 편향(수요일 +5.2% 과대)의 원인을 모델 층위에서 찾은 결과. 후처리 보정은
채택하지 않았다(근거 §5).

## 2. ★ 프론티어 비교는 이 설계로 불가능하다 (실측 확인)

<!-- 이 절을 지우지 말 것. 위 stockout_risk/surplus_rate 차이를 "프론티어 중립 증거"로
     인용하는 것을 막는 유일한 장치다. -->
발주량(`production`)은 **quantile 모델**에서 나오고 그 모델은 두 arm이 동일하다. 실측:

```
364행 중 production 동일 = 361행 (99.2%)
expected 다른 행          = 364행 (100.0%)
production 다른 날짜 3개 = 2025-12-25 / 2025-10-06 / 2025-05-05  ← 전부 event_prior 보정일
```

유일한 차이 채널은 `event_prior.blend` 의 보정비(`blended_exp / exp`)이며, 그건 등록 이벤트
3일에만 걸린다. **따라서 위 `stockout_risk`·`surplus_rate` 차이는 목적함수 효과가 아니라
이벤트 3일의 부산물이다.** 이 수치로 "center calibration이 프론티어를 개선/악화한다"고
말할 수 없다 — 어느 방향으로도 근거가 없다.

**함의**: center 모델 개선은 **고객에게 보고하는 수요 추정치**를 바꾸지만 **발주 결정은
거의 건드리지 않는다.** 프론티어를 움직이려면 quantile 모델(분위수·conformal 재보정)을
건드려야 하고, 그건 이 프로젝트가 이미 지목한 잔여 레버다(under-dispersion σ̂ 1.72× 과소).

## 3. 원인 규명 — 가설 3개를 순차 반증

### ❌ 가설 1: 부스팅 정규화(용량 제약) 때문에 평균 회귀한다 → **반증**
용량을 크게 풀어도 편향이 **오히려 커진다**(20-fold 예비, event_prior 없음):

| | 기본 depth6/leaves31 | 고용량 depth12/leaves255/mcs5 |
|---|---|---|
| 요일 \|WPE\|합 | 0.1707 | **0.1958 (악화)** |
| WAPE | 0.0742 | 0.0735 |
| std비 | 1.168 | 1.139 |

정규화가 원인이면 용량을 풀 때 줄어야 한다. 압축도 거의 안 움직였다.

### ❌ 가설 2: "L1은 중앙값, WAPE/WPE는 합계(평균)" 지표 불일치의 정상적 귀결 → **반증**
이게 맞다면 L1의 **조건부 중앙값 자체는 무편향**이고 잔차 왜도가 WPE를 설명해야 한다.
실측(L1, 52-fold)은 둘 다 아니다:

| 요일 | median(잔차) | mean(잔차) | 잔차 왜도 | WPE |
|---|---|---|---|---|
| 월 | **−9.81** | −4.47 | +0.57 | +0.020 |
| 화 | **−8.67** | −6.76 | +0.23 | +0.030 |
| 수 | **−8.19** | −10.94 | +0.04 | +0.052 |
| 목 | +2.36 | +2.92 | −0.12 | −0.013 |
| 토 | +2.45 | +7.57 | +0.49 | −0.024 |

`median(잔차)` 가 0이 아니다 — 월·화·수에서 **−8~−10 unit 체계적으로 음수**(=과대예측).
즉 L1이 조건부 중앙값을 맞추지 못하고 있다. 그리고 `corr(잔차왜도, WPE) = 0.081` ≈ 0 →
왜도로 설명되지 않는다.

### ✅ 남는 것: 요일별 조건부 중앙값 자체의 miscalibration
지표 아티팩트가 아니라 **실제 모델 결함**이다. 저수요 요일(월·화·수)을 중앙값 수준에서도
과대예측한다. 옛 진단(`docs/weekday_bias_lever_result.md`: dow-blind rolling이 주말 고수요를
섞어 평일을 상향)이 방향은 맞으나, 원점 기준 패널에서 `y_same_dow_*` 앵커 gain이 12.7%로
dow-blind AR(10.5%)보다 커진 뒤에도 편향이 남았으므로(월 +2.0→+2.5, 수 +5.2→+4.7)
**dow-blindness만으로는 완결되지 않는다.** 정확한 메커니즘은 미규명.

⚠️ **미검증**: L2가 왜 이 편향을 줄이는지도 규명하지 않았다(MSE가 큰 오차를 더 벌해 저수요
요일 레벨 분리를 강제한다는 추측은 있으나 검정 안 함).

## 4. 판단 — 채택 보류, architect 결정

L2는 **calibration을 고치고 헤드라인 정확도를 악화**시킨다. 그리고 §2 때문에 **발주 프론티어
근거는 이 실험에 없다.** 그래서 순가치를 데이터로 확정할 수 없다.

- **WAPE가 헤드라인 지표**이므로(측정 헌장) 기본값 교체는 손실로 보인다
- 다만 **수요일 +5.2% 과대예측은 고객에게 보고되는 수요 추정치의 실제 결함**이고 L2가 그걸 절반 이하로 줄인다
- 결정하려면 "우리가 보고하는 것이 조건부 중앙값인가 평균인가"를 먼저 정해야 한다 — 이건 지표 선택 문제이지 모델 품질 문제가 아니다

**헤드라인(`experiments/gwangyo_default.yaml`)은 무변경.** L2는 registry 등록 + 실험 YAML로만 존재한다.

## 5. 후처리 보정을 채택하지 않은 이유 (architect 판단, 2026-07-29)

> "요일까지 후처리하는 건 모델에 허점이 있어 보인다. 크리스마스나 특수일이면 그럴 수 있지만."

이 구분이 이 프로젝트 구조와 정합적이다:

| | 샘플 수 | 트리 학습 가능성 | 처리 |
|---|---|---|---|
| 특수일(크리스마스·명절) | 학습창당 **2~5** | 원리적으로 불가(당일 dummy gain=0으로 실증) | `event_prior` 후처리 정당 |
| 요일 | 요일당 **약 260** | 배워야 함 | 후처리는 결함 은폐 |

부수적으로, 후처리 요일 배수는 이미 프론티어-중립으로 검정된 negative다
(`docs/weekday_bias_lever_result.md`: 9개 조합 전부 매진 gap CI 0 포함).
