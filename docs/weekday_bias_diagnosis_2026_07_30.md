# 요일 편향 — feature 층위 진단: 닫혔다 (2026-07-30)

레버 3개가 negative로 판정된 뒤([[docs/hyperparameter_two_objective_result.md]]) 남은 축이
"feature 층위(dow-aware rolling의 within-dow σ 감소)"였다. **착수 전 진단 결과 그 축도
가치가 없다.** 구현하지 않았다.

측정 조건: 최근 26 fold(= regime shift가 있으므로 확인 구간에서 진단), event_prior 없음,
헤드라인 하이퍼파라미터.

## 1. 결론 — 4가지 측정이 모두 같은 방향

| # | 측정 | 값 | 함의 |
|---|---|---|---|
| A | 요일 레벨 **분리도** (예측 요일평균 std / 실측) | **0.928** | 모델이 요일 레벨을 이미 93% 재현한다 |
| B | 요일을 완벽히 맞췄을 때 잔차 σ 개선 상한 | **−7.7%** (음수) | within-dow σ(23.86) > 현재 잔차 σ(22.15) — **이미 within-dow 노이즈보다 낮다** |
| C | 잔차 분산 중 **요일이 설명하는 비율** | **R² = 0.087** | 일별 오차의 91%는 요일과 무관 |
| D | **오라클 상한**(미래 정보로 요일 gap 완전 제거) | WAPE −**0.467pp** | 달성 불가한 이론 상한이 0.47pp |

## 2. B가 결정적이다 — feature 층위의 여지가 물리적으로 없다

```
within-dow σ (실측)  = 23.86   ← 요일을 완벽히 알아도 남는 노이즈
between-dow σ        = 39.43
현재 잔차 σ          = 22.15   ← 이미 within-dow σ보다 작다
```

옛 문서가 남긴 미검정 가설은 *"dow-aware rolling이 within-dow σ를 줄일 수 있다"* 였다
(`weekday_bias_lever_result.md` 마지막 절). **그런데 현재 잔차 σ가 이미 within-dow σ보다
낮다.** 즉 모델은 요일 내부 변동보다 더 정밀하게 맞히고 있고, 요일 정보를 더 넣어서 줄일
여지가 남아 있지 않다. 이 방향의 개선 상한은 **음수**다.

⚠️ 해석 주의: 잔차 σ < within-dow σ 인 것은 모델이 요일 외 정보(캘린더·날씨·최근추세)로
within-dow 변동의 일부를 이미 설명한다는 뜻이다. 요일 축을 더 파는 것과는 별개 문제다.

## 3. C — 요일 편향은 "평균의 이동"일 뿐 일별 오차의 주원인이 아니다

잔차 분산 중 요일이 설명하는 비율 **R² = 0.087**. 91.3%는 요일과 무관한 변동이다.
요일 gap의 절대 크기도 작다:

| 요일 | 실측 평균 | 예측 평균 | gap (개/일) |
|---|---|---|---|
| 월 | 213.4 | 220.6 | +7.2 |
| 화 | 211.4 | 219.7 | +8.3 |
| **수** | 200.1 | 211.8 | **+11.7** |
| 목 | 230.3 | 221.3 | −9.0 |
| 금 | 228.4 | 227.8 | −0.7 |
| 토 | 300.3 | 300.3 | −0.1 |
| 일 | 288.5 | 288.3 | −0.1 |

최대 편향(수요일) **11.7개/일 = 총량의 4.9%** 인데, **일별 잔차 σ는 22.1개**다.
요일 gap은 σ의 **0.53배** — 일별 노이즈에 묻히는 크기다. 이것이
`weekday_bias_lever_result.md` 가 "요일 특정 보정 = 프론티어-중립"으로 판정한 메커니즘과
정확히 같다(dow 잔차 std가 평평하므로 어느 요일을 낮추든 같은 waste면 같은 매진).

## 4. D — 이론 상한조차 0.47pp

미래 정보로 요일 gap을 **완전히** 제거하면(달성 불가):

```
현행    WAPE 0.07280 · 요일|WPE|합 0.1744
오라클  WAPE 0.06813 · 요일|WPE|합 0.0000   → WAPE −0.467pp
```

**어떤 방법도 이보다 잘할 수 없다.** 그리고 이 0.47pp는 발주 결정을 거의 바꾸지 않는다 —
프론티어를 움직이는 것은 center가 아니라 quantile임이 이미 실측됐다
(`expected_objective_result.md` §2: L1/L2 A/B에서 production 364행 중 361행 동일).

## 5. A — 요일 미분리 가설도 부분 반증

요일 평균 레벨의 std: 실측 39.43 vs 예측 **36.60 → 분리도 0.928.** 모델이 요일 레벨을 이미
93% 재현한다. "요일을 못 배운다"가 아니라 **남은 7%가 저수요 요일 쪽에 편중**된 것이다
(월·화·수 +, 목 −, 금·토·일 ≈0). 토·일은 gap이 사실상 0이므로 "고수요 요일을 눌러쓴다"는
단순 수축 스토리도 성립하지 않는다.

<!-- 이 문장을 지우지 말 것. 재착수 방지 장치다. -->
**요일 편향은 더 파지 않는다.** 이론 상한 0.47pp이고, 그 상한을 다 먹어도 발주 결정은
거의 안 바뀐다. 남은 실제 레버는 **quantile / spread 축**(under-dispersion σ̂ 1.72× 과소)
하나이며, 그것이 프론티어를 직접 움직이는 유일한 축이다.

## 7. 남은 의문 (미규명, 추적 안 함)

- 왜 저수요 요일(월·화·수)에 편중되는가 — 조건부 중앙값 miscalibration의 메커니즘. §4 상한이
  작으므로 규명 가치가 낮다고 판단해 중단한다.
- regime shift의 원인(최근 구간에서 요일 편향이 더 큼, 144 config 전부) — 데이터 축 변화일
  수 있다. 요일 추적을 멈추므로 함께 보류하되, **다른 이유로 최근 데이터를 재검토할 때 같이
  본다.**
