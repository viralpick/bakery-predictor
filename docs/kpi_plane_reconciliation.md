# KPI 평면 정산 — 옛 헤드라인 vs 백본 (2026-07-31)

KPI 평면 백본 편입 4/4단계. 옛 `scripts/unified_policy_kpi.py` 헤드라인과 새
`bakery harness-run experiments/gwangyo_kpi.yaml` 산출을 **축별로** 맞춘 기록.

## 1. ★ 결론 — 옛 수치는 재현된다. 축을 잘못 맞추면 안 된다

내가 3단계에서 낸 `−26~28%` 와 옛 헤드라인 `−37~45%` 는 **다른 축이었다.**
옛 문서(`docs/phase7/gwangyo_waste_kpi_remeasure.md:114`)가 이미 두 축을 분리해뒀다:

| 축 | 정의 | 옛 헤드라인 | 새 백본(52-fold) |
|---|---|---|---|
| `ΔvsA` (하한) | 모델(B) vs 아띠제 **실측**(A) — **잣대 다름** | −30.9 ~ −41.2% | **−26.1 ~ −27.9%** |
| **`ΔvsB` (공정)** | 모델(B) vs 아띠제 **시뮬**(B) — 같은 잣대 | **−32.4 ~ −46.6%** | **−33.4 ~ −35.0%** |
| censoring gap | 같은 정책을 A→B로 재측정한 차이 | **+10.2%** | **+10.97%** |

**censoring gap이 +10.2% → +10.97% 로 거의 같다.** 잣대 효과의 크기가 독립적으로 재현됐고,
이것이 두 파이프라인이 같은 것을 재고 있다는 가장 강한 증거다.

⚠️ **헤드라인으로 인용할 축은 `ΔvsB`(공정)** 이다. `ΔvsA` 는 A가 실측 폐기(censored)라
절감을 과소평가하는 **하한**이다. 옛 헤드라인 "−37~45%"도 `ΔvsB` 축이었다.

**총비용 기준 우리 모델이 아띠제 대비 −23.6%** (37.71M vs 49.35M, 동일 B 잣대).
전체매진 손실을 다 물어도 폐기 절감이 압도한다.

### ★ 트레이드오프가 여기서 정확히 보인다
아띠제 실생산을 B로 재면 **전체매진 부족량이 1.8개(0.3%일)** 다 — 과발주하니 거의 안 매진된다.
우리는 1,986~2,238개(31~32%일)로 늘어난다. **폐기 −33~35% 의 대가가 이것이다.**
헌장이 폐기를 1차 KPI로 두므로 방향은 맞지만, 이 표 없이 "−35% 절감"만 인용하면
대가를 숨기는 것이다.

## 3. 옛↔새 차이의 축별 분해

`ΔvsB` 가 옛 −32.4~−46.6% → 새 −33.4~−35.0% 로 **범위가 좁아졌다.** 원인 축:

| 축 | 옛 | 새 | 방향 |
|---|---|---|---|
| **fold 규약** | 8 fold × 8주 (224일 × 50품목) | **52 fold × 7일** (364일 × 58품목) | 평가 구간·품목이 넓어져 극단값이 희석 |
| **정책 수** | 5종(quantile / nk15 / nk30 / conformal / reimpl) | 2종(category_total / distributional_total) | 옛 범위 하단(−46.6%)은 **nk15**인데 NK는 과적합으로 폐기됨 |
| **원가율** | 0.30 전역 | **품목별 0.40 / 0.60** | 매출가중 0.491 → 폐기비용 절대값이 커지나 **비율은 대부분 상쇄** |
| **배분 leakage** | 미수정(대상일 직전 실적 사용) | **수정**(`lead_days` 경계) | 배분의 2.09%가 재배치(PR#74 실측) → 약간 불리 |
| **리드타임** | 0 | **5일** | 총량 정확도 −0.536pp(C1 실측) → 불리 |
| **SKU 품절율** | 날별 평균(동일) | 날별 평균 | 변화 없음 |

**옛 범위 하단 −46.6%가 사라진 주된 이유는 NK 정책 제거**다(과적합 판정). 남은
차이(−32.4 → −33.4)는 fold 규약·리드타임·leakage 수정이 섞인 것이며, **전부 새 값이
더 보수적인 방향**이다. 즉 새 수치가 낮아진 것은 성능 저하가 아니라 **측정이 엄격해진 것**이다.

⚠️ 절대 KRW는 비교 대상이 아니다 — 옛 실행 일부는 flat 3,000원/개였고 원가율도 0.30이었다
(옛 문서 자체가 이를 명시). **% 축만 비교 가능**.

## 4. 음수 폐기 — 여전히 열린 항목

| 항목 | 값 |
|---|---|
| 음수 폐기 행 | **494 / 13,359 (3.70%)** |
| 음수 합 | −1,010개 |
| `clip` 효과 | 폐기 총량 **+5.54%** |

기본값은 `waste_clip_negative=True`(음수를 0으로)이고, 매 실험 산출의
`actual_waste_clip_effect_pct` 컬럼에 박힌다. **아띠제 확인 필요**: 재고정보 `QT_OUT` 이
음수인 날은 재고 정정인가, 반품 상계인가?
- `clip(0)` 이면 A basis 폐기가 19,257개 → `ΔvsA` 가 덜 유리
- 원본 유지면 18,247개 → `ΔvsA` 가 더 유리

⚠️ **판매 반품(`SALES_FG=1`, 1.79%)은 별개 소스**이며 전처리 백본이 이미 net-out한다
(`bonavi_loader.py:377` / `load_returns_v2`). 음수 폐기와 혼동 금지.

## 5. 무엇이 백본으로 옮겨졌나

| 관점 | 옛 위치 | 새 위치 |
|---|---|---|
| 폐기비용 / 총비용 | `scripts/unified_policy_kpi.py` | `evaluation/order_kpi.basis_sim` |
| A basis(아띠제 실측) | 같음 | `evaluation/order_kpi.basis_actual` |
| **아띠제 절감률** | 같음 | `evaluation/order_kpi.compare_to_actual` |
| 매진시각 / 조기매진율 | 같음 | `evaluation/order_cost.stockout_timing` |
| 품목 배분 | `cli.py:2331` (harness 밖) | **`harness/backtest_core` (`order_level: item`)** |
| 진입점 | `python scripts/unified_policy_kpi.py` | **`bakery harness-run experiments/gwangyo_kpi.yaml`** |

`scripts/unified_policy_kpi.py` 는 **얇은 wrapper로 축소**했다(중복 계산 0). 옛 5정책
비교(nk15/nk30/conformal 포함)가 필요하면 그 스크립트를 쓰되, **헤드라인 수치는 백본에서 낸다.**

## 6. 재현

```bash
uv run bakery harness-run experiments/gwangyo_kpi.yaml   # KPI 표 → reports/gwangyo_kpi/kpi.csv
```
`kpi: true` 는 `order_level: item` 을 요구하고(`SpecError` 로 강제), 기본은 둘 다 off라
헤드라인 실험(`gwangyo_default.yaml`)은 이 경로를 타지 않는다.
