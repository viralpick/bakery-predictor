# 2026 상반기 편입 + out-of-sample 실측 (2026-07-31)

`보나비 추가 데이터_20260721.xlsx` 로 재고 라벨을 2026-06-30까지 확장하고, **모델이 학습에
쓰지 않은 6개월**에서 성적을 처음 측정했다.

## 1. ★결론 — 모델이 미학습 구간에서 버틴다

두 구간을 **나란히** 냈다(`eval_end` 로 구간 고정). 한쪽만 보면 성능 차이인지 구간 차이인지
판별할 수 없다.

| 지표 | 2025 구간 | **2026 포함 구간** | 변화 |
|---|---|---|---|
| 평가 기간 | 2025-01-02 ~ 2025-12-31 | 2025-06-29 ~ 2026-06-30 | — |
| WAPE (category) | 7.791% | 7.913% | +0.12pp |
| WAPE (**distributional**) | 7.753% | **7.744%** | **−0.01pp (유지)** |
| **폐기 절감 ΔvsB** (category) | −33.43% | **−33.93%** | **−0.50pp 개선** |
| **폐기 절감 ΔvsB** (distributional) | −34.99% | **−36.12%** | **−1.12pp 개선** |
| 전체매진일 (category / dist) | 114 / 117 | 128 / 137 | +14 / +20 |
| 아띠제 실측 폐기비용 | 4,447만원 | 4,485만원 | +0.8% (정상) |

**절감폭이 줄지 않고 오히려 커졌다.** 특히 distributional이 −36.12%로 벌어지고 WAPE도 유지된다.

## 2. 순수 미학습 구간만 잘라보면 — 정확도는 나빠진다

2026 구간은 2025 하반기 186일 + 2026 상반기 178일의 혼합이다. 후자만 보면:

| arm | 구간 | WAPE | 잉여율 | 부족일 |
|---|---|---|---|---|
| category_total | 2025 하반기 | **7.21%** | 9.15% | 29일 |
| category_total | **2026 상반기(미학습)** | **8.67%** | 9.03% | 44일 |
| distributional | 2025 하반기 | **6.97%** | 8.60% | 33일 |
| distributional | **2026 상반기(미학습)** | **8.57%** | 7.90% | 59일 |

**정확도는 1.4~1.6pp 나빠진다**(7.2%→8.7% / 7.0%→8.6%). 미학습 구간이니 자연스럽다.
그런데 **잉여율은 오히려 낮아지고**(9.15→9.03 / 8.60→7.90) 그래서 **폐기 절감은 유지·개선**된다.

★해석: **정확도 저하가 발주 성적으로 전이되지 않았다.** 이는 이 프로젝트가 반복 확인한
"프론티어를 움직이는 것은 center가 아니라 quantile"과 일관된다 — center(WAPE)가 나빠져도
발주(분위수)는 견딘다. 대가는 **부족일 증가**(29→44 / 33→59)다.

⚠️ 2026 상반기는 **178일**이다(181일 중 3일이 dropna로 탈락). 단일 반기이므로 이 수치를
"연간 성적"으로 일반화하면 안 된다.

## 3. ★★가는 길에 잡은 함정 3개 — 전부 "정상 실행 + 조용히 틀린 결과"

데이터 확장은 상류에서 성공해도 **하류 소스가 따라오지 않으면 결과만 틀린다.** 실패로
드러나지 않아 더 위험하다.

| # | 증상 | 원인 | 교정 |
|---|---|---|---|
| 1 | 두 구간이 **완전히 동일한 결과** | `weather_observed` 가 2025-12-31에서 끝나 2026 181일이 `dropna()` 로 전부 탈락 | 날씨 전 구간 재수집(4,014행) |
| 2 | 2026 구간에서 아띠제 폐기 **반토막**(4.45M→2.42M), 절감률 **−33%→+22%** 로 부호 반전 | `REAL_INVENTORY_XLSX_PATH` 가 `master_xlsx`(2025-12까지) 고정 → 2026 아띠제 폐기가 0으로 집계 | `additional_xlsx` 로 교체 |
| 3 | 배수 정렬도·마감시각 오측정 | **매장 코드 혼동** — `1000000047`=광교 / `1000000009`=삼성타운 | 광교로 재측정, 근거 교체 |

**신호를 읽는 법**: ②는 "우리 수치는 그대로인데 아띠제만 반토막"이 단서였다. 한쪽만 급변하면
성능이 아니라 **소스 커버리지**를 먼저 의심해야 한다.

⚠️ `ingest-weather` 는 **merge가 아니라 replace** 다. `--start 2025-12-01` 로 부분 백필하면
이전 구간이 사라진다(실제로 3,652행 → 424행으로 날렸고 전 구간 재수집으로 복구). 외부 데이터
갱신 전에는 **백업 필수**.

## 4. 안전성 — 기존 수치는 깨지지 않았다

- 겹치는 구간(2021~2025) **광교 90,938행 전수 대조에서 `QT_MADE`/`QT_OUT` 불일치 0건.**
  `additional_xlsx` 는 master의 상위집합이다.
- `eval_end` 고정으로 2025 구간을 재현했고 **−33.43% / −34.99%** 가 이번 주 보고와 일치한다.
- 백업: `data/_archive/pre_2026_rebuild_20260731_0952/`(bonavi_daily / receipts / multistore / weather)

## 5. 재현

```bash
uv run bakery build-data --no-diagnose      # ⚠️--diagnose가 기본값이라 안 쓴다
uv run bakery build-multistore
uv run bakery harness-run experiments/gwangyo_kpi_2025.yaml   # 옛 구간 재현

```

## 6. 남은 것

- **커버리지 가드 부재** — 상류 확장 시 하류 소스가 따라오지 않는 것을 자동으로 잡는 장치가
  없다. 위 함정 3개 전부 수동으로 발견했다. `build_features` 후 타깃 구간 커버리지 검증을
  넣어야 한다.
- 배수 프리미티브(`models/batch_rounding.py`)가 **아직 배분 체인에 배선되지 않았다** —
  총량 보존 라운딩은 구현·검증 완료이나 harness가 쓰지 않는다.
- AX 제시량(`suggested_qty`) 비교 축 미구현.
